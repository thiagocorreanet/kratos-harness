# Issue #130 feature document template evidence

Date: 2026-08-18

## Scope

This evidence closes [issue #130](https://github.com/thiagocorreanet/kratos-harness/issues/130).
The change replaces the four placeholder feature documents with deterministic,
purpose-specific templates and makes `prd-present` distinguish a missing PRD,
an untouched template, a named missing section, and a complete document.

## Acceptance evidence

| Acceptance criterion | Evidence |
| --- | --- |
| Initialization is pure, byte-identical, and idempotent | `tests/feature-documents.test.ts` asserts every generated byte; `tests/init-skeleton.test.ts` seals clock and randomness; `tests/init-command.test.ts` proves the second plan preserves every destination. |
| An untouched feature copy fails distinctly | `tests/feature-documents.test.ts` and `tests/gate-facts.test.ts` assert `gate.prd_untouched` in the pure evaluator and a composed evidence bundle. |
| A missing required section names the section | The same suites assert `gate.prd_section_missing` and `Missing required section: Success metrics`. |
| A completed document passes without gate I/O | The domain inspector returns `complete`; composition performs the durable read and passes a closed `PrdDocumentObservation` into the pure evaluator. |
| Templates are valid, host-neutral Markdown | Exact template assertions reject Claude/Codex names; the repository formatting, spelling, and English-only checks pass. |
| Required names have one runtime source | `FEATURE_DOCUMENTS` derives template headings and `requiredSections` from the same section definitions used by PRD inspection and tests. |
| Filled examples exist | `fixtures/feature-documents/complete` contains a completed PRD, design, task plan, and reviewer summary. |

## Impact

- **Compatibility:** Additive reason catalog revision `1.4.0`; revisions 1.0
  through 1.3 remain byte-preserved. No schema, approval, or digest contract
  changes.
- **State:** Existing files are not migrated. A future `init` compares the new
  deterministic bytes through the existing managed mutation pipeline.
- **Security:** No authority was added. PRD reads remain project-relative and
  use the existing durable filesystem observation port; gate evaluation stays
  free of I/O.
