# Issue 25 Initialization Evidence

[#25](https://github.com/thiagocorreanet/mestre-yoda/issues/25) (`SDD-01`).
Every acceptance criterion maps to a named test, and what is not covered says
so.

## Acceptance criteria

| Criterion | Evidence |
| --- | --- |

## What is not covered

**Differential tests against the legacy scenarios.** The issue asks for them
and this work does not deliver them. The differential harness compares this
runtime against a captured predecessor, and no `init` capture exists: the
inventory carries the command and its flag names under hash-only provenance,
with no behavioral capture behind them. Producing that capture is `CMP-05`.

This is why the nine initialization rows move to `in_progress` rather than
`parity`, and why parity stays `0 / 400 (0.00%)`. The semantics this runtime
implements are its own contract, chosen to satisfy the issue; claiming a
behavioral row on the strength of a frozen name would make the parity number
describe something other than parity.

**Real-host end-to-end runs.** Initializing a project and then driving Claude
Code or Codex against it belongs to `QAL-08` and the adapter issues.

## Defect found while integrating

Publishing a file at the project root failed against the Node adapter, while
passing against the fake. `parentPath` returned an empty string for a path with
one segment, and an empty path is refused as escaping the project, so
`replaceFile`, `linkFileExclusive`, and `removeFile` rejected every root
destination -- `CLAUDE.md` and `AGENTS.md` among them.

`RUN-05a` added the project-root sentinel to `inspect` but exercised it only
through the fake, whose parent computation differs. The fix names the sentinel
in `parentPath`, and the case now lives in the shared port contract suite, so
the fake and the Node adapter answer it together.
