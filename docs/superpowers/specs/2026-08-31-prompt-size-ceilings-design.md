# Objective Spec: Prompt Size Ceiling Enforcement

Date: 2026-08-31
Status: APPROVED
Approval source: GitHub issue #qal-10 and approved brainstorming design

## 1. Problem and desired outcome

As Kratos introduces host skills, phase agent prompts, managed instruction blocks, and document templates, prompts risk growing quietly until models degrade in adherence to key constraints. A long instruction file measurably reduces instruction following, where added lines compete for attention with existing constraints.

The desired outcome is a deterministic ceiling per prompt category enforced in CI. Any prompt that exceeds its ceiling fails the build immediately with an actionable error naming the file, the measured character count, and the limit. Uncategorized prompts fail rather than passing unchecked.

## 2. Measurement unit and rules

- **Measurement Unit**: Unicode character count (UTF-8 characters). Character count directly measures raw prompt mass and attention budget without being gameable through line-wrapping, while remaining deterministic and independent of model-specific tokenizers.
- **Rendered Form Measurement**: Prompts are measured in their final rendered form (what the model actually receives). For static prompt files (e.g. host skills, orchestrator prompt), measurement is performed on the file content. For generated prompts (phase agents, managed instruction blocks, feature document templates), measurement is performed on the output generated by the runtime effects.
- **Host Neutrality**: Both Claude Code, Codex, and Antigravity distributions are measured under identical rules and category ceilings. No prompt may be trimmed for one host and left long for another.
- **Breach Policy**: The mandatory response to a ceiling breach is factoring out detailed guidance or examples into referenced reference documents (e.g., in `docs/` or separate markdown files) and linking to them, rather than raising the ceiling number.

## 3. Categories, ceilings, and reasoning

| Category | Ceiling (chars) | Target Surfaces | Rationale |
| --- | --- | --- | --- |
| `host-skill` | 6,000 | `distribution/*/skills/kratos/SKILL.md` (Claude Code, Codex, Antigravity) | Skill instructions route lifecycle commands, interview relays, and phase handoffs. 6,000 characters provides sufficient space for relay mechanics without overwhelming the host skill context. |
| `phase-agent-prompt` | 8,000 | 5 phase agents (`prd-researcher`, `spec-planner`, `spec-reviewer`, `code-implementer`, `implementation-evaluator`) rendered in host agent definitions | Defines role boundaries, uncertainty fail-closed rules, language policy, document paths, and output machine blocks. 8,000 characters protects model attention on critical constraints and checklists. |
| `orchestrator-prompt` | 1,000 | `distribution/claude-code/agents/kratos-orchestrator.md` | Pure relay agent connecting host events to runtime; carries no independent workflow logic or decisions. |
| `managed-instruction-block` | 6,000 | Managed section in `CLAUDE.md`, `AGENTS.md` produced by `kratos init` across stack profiles | Contains host-specific tool permissions and stack-detected rules. 6,000 characters accommodates varied stack configurations without bloating project root instruction files. |
| `feature-document-template` | 3,500 | Feature templates in `.brain/02-features/` (`00-prd.md`, `01-design.md`, `02-tasks.md`, `03-summa.md`) | Structured scaffolding and section-by-section guidance. 3,500 characters keeps templates focused on structure rather than embedding expansive documentation. |

## 4. Architecture and components

1. **Domain Catalog (`packages/runtime/src/domain/prompt-ceilings/`)**:
   - Declares the canonical category catalog, category ceilings, rationale strings, and target file mapping/discovery rules.
   - Exports pure functions to evaluate a prompt against its category limit: `evaluatePromptCeiling(category, measuredText, path)`.
   - Exports the full inventory catalog of shipped prompt surfaces.

2. **CI Script (`scripts/check-prompt-ceilings.mjs`)**:
   - Collects all shipped prompt surfaces across `distribution/` and runtime `skeletonEffects` (for multiple hosts and stack profiles).
   - Verifies that every discovered prompt is categorized. If an unknown prompt is encountered, it fails with:
     `Uncategorized prompt detected: <path>. Every prompt the distribution ships must be declared under a category.`
   - Evaluates rendered character counts against category limits.
   - In case of a breach, exits with status 1 and prints:
     `Prompt size ceiling exceeded in <file>: measured <measured> chars, limit is <limit> chars (category: <category>).`
   - Integrated into `package.json` under `"prompts:ceilings:check"` and included in `"verify"`.

3. **Automated Vitest Tests (`tests/prompt-ceilings.test.ts`)**:
   - **Fixture Breach Test**: Tests an intentionally oversized fixture prompt and asserts that it fails with the exact diagnostic message naming file, measured count, and limit.
   - **Inventory Completeness Test**: Asserts that every shipped distribution file matching prompt surfaces is declared in the category inventory, and that uncategorized files trigger a failure.
   - **Current Distribution Test**: Measures every prompt currently shipped by the repo and verifies that all pass with zero breaches.
   - **Host Parity Test**: Verifies identical ceiling enforcement across Claude Code, Codex, and Antigravity.

4. **Documentation and Baseline Evidence**:
   - Records current prompt measurements in `docs/verification/` as baseline evidence.
   - Documents prompt ceiling policies and breach remediation in architecture documentation and `contributing/workflow.md`.

## 5. Acceptance criteria verification

- [x] A prompt over its ceiling fails CI, and the failure names the file, the measured size, and the limit.
- [x] Every prompt the distribution ships falls under a declared category, and a new prompt file with no category fails rather than passing unchecked.
- [x] The check runs on the rendered form when the rendered form differs from the source.
- [x] Both distributions (and Antigravity) are measured by the same rule.
- [x] The current prompt surface passes without any ceiling being chosen to accommodate it.
