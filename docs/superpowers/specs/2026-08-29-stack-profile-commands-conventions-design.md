# Stack Profile Commands and Conventions Design

Date: 2026-08-29
Status: APPROVED
Issue: #142 (`SDD-17`)
Dependencies: #138 (`FND-08`), #134 (`ADP-02a`)
Approval source: the user's approved brainstorming dialogue

## Problem and outcome

`.brain/01-architecture/stack-profile.md` currently reports only stack markers
observed at the project root. Phase agents also need the exact project commands,
meaningful paths, existing conventions, implementation languages, and resolved
language policy. Stack markers cannot supply those facts honestly: observing a
`package.json` does not prove that `npm test` is the project's test command.

Initialization will therefore persist a typed project profile supplied by the
host interview and render the Markdown document from that state. Detection
remains offline, root-entry-only evidence and never invents commands, paths, or
conventions.

## Authority and contracts

The runtime owns the profile's schema, resolution, persistence, rendering, and
diagnostics. Claude Code and Codex collect and relay the same answers; prompts
do not infer values or decide readiness.

`host.init-answers@1.3.0` accepts an optional partial `projectProfile`.
`state.project-config@1.3.0` persists a complete profile with these closed
groups:

- `commands`: `test`, `lint`, `build`, and `run`.
- `paths`: `source`, `tests`, and `configuration`.
- `conventions`: `directoryLayout`, `naming`, and
  `implementationLanguages`.

Every leaf has one explicit state:

- `{ "status": "resolved", "value": ... }`
- `{ "status": "not-applicable", "reason": "..." }`
- `{ "status": "unresolved" }`

One command set describes the whole project, including polyglot repositories.
Commands are exact single-line strings run from the project root. Paths are
non-empty lists of safe project-relative references. Implementation languages
are a unique non-empty list such as `["TypeScript"]`; directory layout and
naming are non-empty text.

The existing `language` policy remains the only authority for human language.
The profile's implementation languages mean programming languages. The
renderer mirrors the resolved policy from #138 without duplicating it in the
new profile.

## Resolution and regeneration

Each field resolves independently using this precedence:

1. An explicit initialization answer.
2. The value persisted in a current project configuration.
3. `{ "status": "unresolved" }`.

Omitting a field during reinitialization preserves it. Explicitly supplying
`unresolved` clears it. This makes `skeletonEffects` pure after composition has
observed and resolved all inputs.

The generated Markdown contains, in order, detected stacks, commands, paths,
conventions, and language policy. A stable placeholder such as
`<UNRESOLVED: projectProfile.commands.test>` makes every missing answer visible.
`not-applicable` renders its reason and counts as answered.

The file states prominently that `kratos init` regenerates it, manual edits are
not authoritative, and the typed initialization answers must be changed
instead. Stack evidence remains honest for recognized, unrecognized, and
multi-stack roots; it supplies no profile defaults.

## Compatibility and diagnostics

Migration from project configuration 1.2.0 to 1.3.0 preserves all existing
state and creates unresolved profile leaves unless migration answers provide
values. Ordinary operations refuse an older configuration with the new stable
`profile.config_migration_required` reason rather than reusing a model-routing
reason.

`kratos doctor` adds a `stack-profile` check:

- `pass` when the generated bytes match the authoritative state and no field is
  unresolved;
- `warn` when fields are unresolved, the document is missing, or its bytes
  drifted from the deterministic renderer;
- `fail` when the destination is unreadable or not a file, or authoritative
  state is invalid.

Diagnostics list unresolved field paths and never parse free-form Markdown to
recover answers. Initialization and diagnostics never execute configured
commands.

## Validation and security

- Commands are non-empty single-line strings no longer than 2,048 characters.
- Reasons are non-empty single-line strings no longer than 256 characters.
- Paths are at most 512 characters and refuse absolute, drive-qualified,
  backslash, parent-segment, URI, and control-character forms.
- Convention text is non-empty, single-line, and at most 1,024 characters.
- Implementation-language labels are at most 64 characters.
- Human-provided values are escaped when rendered so they cannot change the
  Markdown structure.

Configured commands remain inert data during init and doctor. A phase agent may
later run them under the host's normal permission policy; this change grants no
new execution authority.

## Verification

Tests must prove schema closure and validation, fieldwise preservation and
override, explicit clearing, migration, byte-exact rendering for recognized,
unrecognized, and multi-stack projects, two-run idempotence, doctor readiness
classification, and Claude/Codex relay parity. Narrow tests run before the full
`npm run verify` gate, and issue evidence maps every acceptance criterion to
reproducible output.
