# Project Initialization Implementation Plan

Implements the design in
[`2026-08-13-project-initialization-design.md`](../specs/2026-08-13-project-initialization-design.md)
for issue [#25](https://github.com/thiagocorreanet/mestre-yoda/issues/25)
(`SDD-01`).

## Global constraints

- Test-first: write the failing assertion, watch it fail for the stated reason,
  then implement.
- Generation is a pure function of answers, stack profile, and contract
  version. No clock, no identifier, no iteration order reaches a generated byte.
- Coverage stays at 100% on all four measures.
- Source, tests, comments, and commits in English.

**Files:**

- Create: `schemas/init-answers.v1.schema.json`

- Create: `tests/init-answers.test.ts`

  requires

**Interfaces:**

- Produces: `InitAnswersV1`, `validateInitAnswers(value, registry)`, and the
  documented default for every optional field.

- [ ] **Step 1: Write the contract tests**

A minimal document validates. Every optional field has a default, and the
validated result reports which defaults were applied, so the caller can tell a
person what they did not choose.

An unknown key is refused rather than ignored: silently dropping an answer is
how a user believes they configured something they did not.

- [ ] **Step 2: Verify RED, add the schema, regenerate types**

Run: `npx vitest run tests/init-answers.test.ts && npm run contracts:check`

### Task 2: Stack profiling

**Files:**

- Create: `packages/runtime/src/domain/init/stack.ts`
- Create: `tests/init-stack-profile.test.ts`

**Interfaces:**

- Consumes: observed repository evidence (manifest presence and content).
- Produces: `profileStack(evidence): StackProfile`, pure.

- [ ] **Step 1: Write the totality property**

Detection never rejects. Over generated evidence sets, `profileStack` always
returns a profile, and an unrecognized project yields a profile that says so
rather than an error — a project the tool does not recognize is still a project
it must initialize.

- [ ] **Step 2: Write the recognition table**

One case per supported stack, each asserting the recorded evidence as well as
the verdict. A profile that names a stack without naming why is a profile
nobody can check.

- [ ] **Step 3: Verify RED, implement, verify GREEN**

The classifier is domain code and cannot reach a filesystem; the observation is
made by the caller through existing ports.

- [ ] **Step 4: Commit**

```bash
git commit -m "feat: profile a project stack from repository evidence"
```

### Task 3: The generated skeleton

**Files:**

- Create: `packages/runtime/src/domain/init/skeleton.ts`
- Create: `tests/init-skeleton.test.ts`

**Interfaces:**

- Produces: `skeletonEffects(answers, profile): readonly Effect[]`, pure.

- [ ] **Step 1: Pin the allowlist**

```ts
it("generates exactly the frozen initialization surface", () => {
  expect(destinationsOf(skeletonEffects(answers, profile))).toEqual(FROZEN);
});
```

`FROZEN` is the list from the design, read from the inventory rather than
retyped, so a path that drifts from the oracle fails here rather than shipping.

- [ ] **Step 2: Prove generation is pure**

The same inputs produce byte-identical effects twice, asserted on content. A
second assertion runs the generator with a clock and an id generator that throw
if called.

- [ ] **Step 3: Host selection**

`--host` narrows the surface: a project that enabled only one host generates
only that host's files, and the `.brain` skeleton either way.

- [ ] **Step 4: Verify GREEN and commit**

```bash
git commit -m "feat: generate the initialization skeleton"
```

### Task 4: Managed sections

**Files:**

- Create: `packages/runtime/src/domain/init/managed-section.ts`
- Create: `tests/init-managed-section.test.ts`

**Interfaces:**

- Produces: `planManagedFile(existing, generated, authorization)`, pure,
  returning the content to write or a typed refusal.

- [ ] **Step 1: Write the three cases and the two malformed ones**

Absent, marked, and unmarked-without-authorization. Then a section whose end
marker precedes its begin marker, and one that appears twice: both refused as
`runtime.state_corrupt` rather than repaired by guessing which was meant.

- [ ] **Step 2: Prove preservation byte-for-byte**

A marked file with content before and after the section keeps both exactly,
including trailing whitespace and line endings. This is the assertion that
matters most in the whole issue: it is a person's file.

- [ ] **Step 3: Authorization**

`--merge` appends the section to an unmarked file; `--force` replaces the file.
Neither is inferred from the absence of the other.

- [ ] **Step 4: Verify GREEN and commit**

```bash
git commit -m "feat: merge managed sections without touching user content"
```

### Task 5: The command

**Files:**

- Create: `packages/runtime/src/composition/init.ts`
- Modify: `packages/runtime/src/domain/cli/**` for the frozen flags
- Create: `tests/init-command.test.ts`, `tests/init-fault-campaign.test.ts`

**Interfaces:**

- Consumes: discovery, the answers contract, the profiler, the skeleton, the
  managed-section planner, `previewPlan`, and `applyPlan`.
- Produces: the `init` command handler and its result projection.

- [ ] **Step 1: Write the idempotency assertion**

```ts
it("decides there is nothing to do the second time", async () => {
  await runInit(project, answers);
  expect(await previewInit(project, answers)).toEqual({ kind: "noop" });
});
```

The first run passing proves nothing; only the second proves nothing moved.

- [ ] **Step 2: Write the reporting assertion**

The result names every destination as created, updated, or preserved. A person
needs to know which of their files the tool touched more than they need a count.

- [ ] **Step 3: Write the flag table**

All seven frozen flags, including the usage failure when `--answers` and stdin
are both supplied. A precedence rule nobody can remember is worse than a
refusal.

- [ ] **Step 4: Fault campaign**

Interrupt the init transaction at every mutating durable boundary and assert
the project is untouched or complete, reusing the campaign shape `RUN-05` and
`RUN-07` already use.

- [ ] **Step 5: Verify GREEN and commit**

```bash
git commit -m "feat: implement the init command"
```
