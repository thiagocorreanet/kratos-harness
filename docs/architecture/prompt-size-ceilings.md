# Prompt size ceiling architecture and policy

Issue [#qal-10](https://github.com/thiagocorreanet/kratos-harness/issues/qal-10)
defines the prompt size ceiling policy and deterministic enforcement mechanisms
for all prompt surfaces shipped by Kratos distributions.

## 1. The problem of prompt bloat

As Kratos introduces host skills, phase agent prompts, managed instruction
blocks, and document templates, prompts risk growing quietly until models
degrade in adherence to critical constraints.

In large language models, an instruction file that grows excessively dilutes
the model's attention budget. Added lines compete for attention with existing
constraints, checklists, and machine-readable output formats. Rather than
improving guidance, unconstrained prompt growth measurably reduces instruction
following, leading to skipped verification steps, format hallucinations, or
ignored boundary rules.

To protect model performance and instruction fidelity, Kratos enforces
deterministic character ceilings per prompt category in continuous integration.
Every prompt shipped or generated by Kratos is governed by an explicit ceiling,
and any breach fails the build immediately.

## 2. Measurement unit and rules

- **Measurement Unit**: Unicode character count (UTF-8 characters). Character
  count directly measures raw prompt mass and attention budget without being
  gamed through line-wrapping or whitespace tricks, while remaining deterministic
  and completely independent of host- or model-specific tokenizers.
- **Rendered Form Measurement**: Prompts are measured in their final rendered form
  (what the model actually receives). Static prompt files (e.g. host skills,
  orchestrator prompt) are measured from their on-disk file content. Generated
  prompts (phase agents, managed instruction blocks, feature document templates)
  are measured on the output generated by runtime effects (`skeletonEffects`).
- **Host Neutrality**: All supported host distributions (Claude Code, Codex, and
  Antigravity) are measured under identical category ceilings and rules. No prompt
  may be trimmed for one host while left oversized for another.
- **Uncategorized Prompt Prevention**: Every prompt surface shipped by the
  distribution must be cataloged under an approved category. An unmapped prompt
  surface fails continuous integration rather than passing unchecked.

## 3. Categories, ceilings, and rationale

| Category | Ceiling (chars) | Target Surfaces | Rationale |
| --- | --- | --- | --- |
| `host-skill` | 6,000 | `distribution/*/skills/kratos/SKILL.md` (Claude Code, Codex, Antigravity) | Skill instructions route lifecycle commands, interview relays, and phase handoffs. 6,000 characters provides sufficient space for relay mechanics without overwhelming host skill context. |
| `phase-agent-prompt` | 8,000 | 5 phase agents (`prd-researcher`, `spec-planner`, `spec-reviewer`, `code-implementer`, `implementation-evaluator`) rendered in host agent definitions | Defines role boundaries, uncertainty fail-closed rules, language policy, document paths, and output machine blocks. 8,000 characters protects model attention on critical constraints and checklists. |
| `orchestrator-prompt` | 1,000 | `distribution/claude-code/agents/kratos-orchestrator.md` | Pure relay agent connecting host events to runtime; carries no independent workflow logic or decisions. |
| `managed-instruction-block` | 6,000 | Managed section in `CLAUDE.md`, `AGENTS.md` produced by `kratos init` across stack profiles | Contains host-specific tool permissions and stack-detected rules. 6,000 characters accommodates varied stack configurations without bloating project root instruction files. |
| `feature-document-template` | 3,500 | Feature templates in `.brain/02-features/` (`00-prd.md`, `01-design.md`, `02-tasks.md`, `03-summa.md`) | Structured scaffolding and section-by-section guidance. 3,500 characters keeps templates focused on structure rather than embedding expansive documentation. |

## 4. Breach remediation policy

When a prompt exceeds its category ceiling, the required remediation is
factoring out detailed guidance, explanations, or examples into referenced
external documentation (such as in `docs/` or separate markdown reference files)
and linking to them from the prompt, rather than raising the category ceiling.

The rules governing ceiling remediation:

1. **Do not raise category ceilings**: Ceilings represent hard attention-budget
   boundaries established to prevent model degradation. They are not bumped to
   accommodate prompt expansion.
2. **Externalize reference material**: Detailed instructions, domain rules,
   and examples belong in external documentation files that agents read on demand
   via tool calls.
3. **Streamline prompt core**: Prompts must focus strictly on role identity,
   critical boundaries, uncertainty handling, document paths, and the machine-readable
   output contract.
4. **Preserve host parity**: When trimming or refactoring a prompt surface shared
   across host adapters, all host variants must receive corresponding refinements.

## 5. Verification and CI integration

Prompt size ceiling enforcement is built directly into the repository quality
pipeline:

- **Domain Catalog (`@kratos/runtime/domain/prompt-ceilings`)**: Exports the
  canonical category catalog (`PROMPT_CATEGORIES`), category limits, surface discovery
  functions (`collectShippedPromptSurfaces`), and pure ceiling evaluation
  (`evaluatePromptCeiling`).
- **CI Check Script (`scripts/check-prompt-ceilings.mjs`)**: Discovers all shipped
  and runtime-generated prompt surfaces, verifies complete categorization, measures
  rendered character counts, and fails with actionable diagnostic messages if limits
  are exceeded or uncategorized prompts are detected.
- **Continuous Integration Pipeline**: Executed via `npm run prompts:ceilings:check`
  and enforced on every PR as part of `npm run verify`.
- **Automated Tests (`tests/prompt-ceilings*.test.ts`)**: Unit and contract tests
  verify zero breaches across current surfaces, test fixture breach rejection,
  enforce uncategorized prompt rejection, and validate host parity.
